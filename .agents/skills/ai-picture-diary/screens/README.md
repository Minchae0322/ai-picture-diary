# 화면 문서 규칙 (프로젝트 전용)

> 화면 문서를 쓰거나 갱신할 때 읽는다. 시안 읽는 절차는 `figma-workflow`, 문체는 `report-style`, docs/ 전체 구조는 `deliverable-structure`.

## 목적
화면 하나 = 문서 하나. 그 화면이 **무엇을 보여주고 무엇을 할 수 있는지**를 코드보다 먼저 확정한다.
`deliverable-structure`의 `docs/domain/`은 서버 도메인 로직용이라 화면이 들어갈 자리가 없다. 화면은 `docs/screen/`에 둔다.

## 위치와 파일명
```
docs/screen/
├── README.md              # 화면 목록 + 탐색 구조 + 공통 규칙 (현행)
└── NN-<슬러그>.md          # 화면 1개 (현행). NN = 시안 번호, 슬러그 = 영문 kebab
```
- 번호는 시안 프레임 번호를 그대로 쓴다. 시안에서 화면이 빠지면 번호를 재사용하지 않는다.
- 화면이 사라지면 문서를 지우지 말고 상단에 `> 폐기: YYYY-MM-DD · 사유` 한 줄을 넣는다.

## 문서 목차 (고정)
```markdown
# NN <화면 이름>

> 시안: <Figma node URL> · 탭: <탭바 위치 또는 없음> · 갱신: YYYY-MM-DD

## 1. 목적
## 2. 진입 / 이탈
## 3. 화면 구성
## 4. 동작
## 5. 상태 (로딩 / 빈 / 에러 / 권한)
## 6. 데이터
## 7. 미정
```
- 3장은 위에서 아래 순서로, 시안 레이어 이름을 괄호에 남긴다 - 나중에 시안과 대조할 유일한 끈이다.
- 5장은 **시안에 없어도 반드시 채운다**(`figma-workflow` 3장). 빈/에러가 비어 있으면 그 화면은 아직 설계가 안 끝난 것이다.
- 7장이 비어 있는 문서를 의심한다. 시안만으로 정해지는 화면은 거의 없다.

## 화면 규칙 파일과의 역할 분담
| | 무엇 | 길이 |
|---|---|---|
| `docs/screen/NN-*.md` | 기능 명세. **읽는 사람용** | 제한 없음 |
| `.claude/skills/ai-picture-diary/screens/NN-<슬러그>.md` | 그 화면을 건드릴 때의 규칙·금지·참조 | 40줄 이내 |

- 스킬은 명세를 복사하지 않는다. 문서를 가리키고, 그 화면에서만 틀리기 쉬운 것만 적는다.
- 같은 내용이 둘에 있으면 문서가 진실이다.

## 작성 순서
1. `figma-workflow` -> `get_metadata`로 프레임 구조를 뽑는다. 텍스트 레이어 이름이 곧 카피다.
2. 화면당 문서 1개를 목차대로 채운다. 모르는 것은 지어내지 말고 7장에 적는다.
3. `docs/screen/README.md`의 목록과 탭 구조를 갱신한다.
4. 화면 전용 규칙이 생겼을 때만 `screens/NN-<슬러그>.md`를 만든다. 없으면 만들지 않는다.

## 갱신
- 시안이 바뀌면 문서가 먼저, 코드가 나중이다. 반대로 하면 문서는 두 번 다시 안 맞는다.
- 구현 중 결정된 것은 7장에서 지우고 해당 장으로 올린다. 7장이 줄어드는 것이 진척이다.

## 하지 말 것
- 문서에 색상 hex·px 좌표 박기 (토큰과 `design-system`이 진실)
- 시안에 있다는 이유만으로 더미 데이터를 스펙으로 적기
- 한 문서에 화면 두 개
