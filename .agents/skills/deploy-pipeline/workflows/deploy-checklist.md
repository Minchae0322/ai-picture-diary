# 배포 체크리스트

`docs/ops/`에 두고 배포마다 확인한다. 팀 규칙에 맞게 항목을 줄이거나 늘린다.

## 배포 전

- [ ] CI가 통과했다 (테스트, ArchUnit, 정적 분석, 시크릿 스캔)
- [ ] 스키마 변경이 있으면 **하위 호환**인지 확인했다 (expand-contract, `db-schema-and-migration` 5장)
- [ ] 마이그레이션 SQL과 롤백 SQL이 준비됐고 `docs/db/` 문서가 있다
- [ ] 마이그레이션 실행 주체가 정해졌다 (파이프라인 / 사람)
- [ ] 새 환경변수가 있으면 **모든 환경**에 등록했다 (`config-and-secrets`)
- [ ] 새 배치가 있으면 cron과 enabled를 환경별로 설정했다 (`batch-and-scheduler` 2장)
- [ ] 구버전과 신버전이 동시에 뜨는 구간을 견디는가 (API 하위 호환)
- [ ] 되돌릴 수 없는 변경(컬럼 삭제, 데이터 삭제)이 포함돼 있는가
- [ ] 배포 시간대가 적절한가 (트래픽, 배치 실행 시각과 겹치지 않는가)
- [ ] **dev에서 한 번 돌려봤다** (마이그레이션, 새 배치, 발송 기능). 스테이징이 없으면 dev가 유일한 리허설이다

## 배포 후 (30분 관찰)

- [ ] 에러율이 배포 전 수준인가
- [ ] p95 응답 시간이 배포 전 수준인가
- [ ] 재시작/OOM이 없는가
- [ ] 새 기능의 로그가 예상대로 찍히는가 (`logging-observability`)
- [ ] 외부 연동 실패율이 정상인가 (`external-api-client`)
- [ ] 배치가 다음 실행에서 정상 동작했는가

## 롤백 판단

되돌린다:
- 에러율이 눈에 띄게 올랐다
- 핵심 기능이 동작하지 않는다
- 원인을 5분 안에 못 찾겠다

되돌리기 전에 확인:
