# 03 AI 생성 중

> 언제: AI 생성 중 화면(03)을 만들거나 고칠 때. "생성 중", "로딩 화면", "AI가 그리는 중", "폴링", "타임아웃", "생성 단계" 언급 시 트리거.

**명세: `docs/screen/03-generating.md`** (시안 `8:91`). 02 위에 덮이는 오버레이.

## 규칙
- 진행 문구는 **서버 단계 이벤트로만** 바꾼다. 타이머로 가짜 진행률을 만들지 않는다.
  시간이 지날 때 바꿔도 되는 것은 "얼마나 기다렸나"뿐이고, 그것은 진행률이 아니다.
- **비율 막대를 두지 않는다.** 불확정 막대조차 "막대"라서 차오르는 것으로 읽힌다.
  기다림은 색연필이 그림을 칠해 나가는 자리(`DrawingBoard`)가 맡는다(`hand-drawn-ui` 5장).
- **판정 전에 특정 감정을 그리지 않는다.** 그림 자리에 서는 것은 감정 아홉 중 하나가 아니라
  어느 과일도 아닌 둥근 과일 하나다 - 결과를 미리 말해 버리면 04 가 싱거워진다.
- 자동 재시도 금지. 이미지 생성은 호출마다 돈이 든다(`llm-integration` 상한 규칙).
- 타임아웃 상한을 반드시 건다. 무한 로딩은 에러 처리를 안 한 것과 같다.
  **폴링 간격과 상한은 `useDiary.ts` 의 `POLL_STEPS` 한 곳에 있다**(1s -> 3s -> 10s, 5분이면 멈춤).
  멈춘 뒤에는 사용자가 직접 물을 길("지금 확인하기")을 반드시 준다.
- **기다림을 강제하지 않는다.** 오버레이에는 늘 빠져나갈 길을 둔다("나중에 볼게요" + 딤 누르기).
  접으면 02 흐름 안에 띠가 남아 무엇이 진행 중인지는 계속 보인다.
- 이미지만 실패하면 **텍스트 결과만으로 04로 보낸다.** 전체 실패로 처리하지 않는다.
- 최소 노출 시간(약 800ms)을 둬 깜빡임을 막는다.
- 사용자가 쓴 원문을 화면에 그대로 보여준다 - 기다림의 근거다.

## 이어서 읽을 것
`llm-integration`, `external-api-client`(타임아웃), `frontend-state`.
