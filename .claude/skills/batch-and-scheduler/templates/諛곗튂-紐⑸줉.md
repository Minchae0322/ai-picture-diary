# 배치 목록

이 프로젝트에서 도는 모든 주기 실행 작업. 배치를 추가·변경·삭제하면 **같은 PR에서** 이 문서를 고친다.
시각은 전부 KST. cron은 Spring 6필드(초 분 시 일 월 요일).

## 요약

| 배치명 | 트리거 | 주기 | 대상 | 실패 시 영향 | 담당 |
|---|---|---|---|---|---|
| 정산 집계 | cron | 매일 02:10 | 전일 거래 | 정산 데이터 미생성, 익일 재실행 가능 | |

## 상세

### 정산 집계

- **프로퍼티**: `app.batch.settlement.enabled`, `app.batch.settlement.cron`, `app.batch.settlement.chunk-size`
- **진입점**: `SettlementScheduler.run()` -> `SettlementBatch.run(LocalDate)`
- **대상과 조건**: 전일(`targetDate`) `tb_transaction` 중 `status = CONFIRMED and settled_at is null`
- **예상 건수 / 소요 시간**: 약 N건 / 약 M분 (측정일: YYYY-MM-DD)
- **중복 실행 방지**: ShedLock `settlement`, `lockAtMostFor = 50m`
- **트랜잭션 단위**: 청크 1,000건
- **실패 처리**: 건별 실패는 `tb_batch_failure`에 기록하고 계속. 실패 100건 초과 시 중단
- **실패 시 업무 영향**: 정산 데이터가 만들어지지 않음. 익일 오전까지 복구되면 업무 영향 없음
- **재실행 방법**: `POST /internal/batch/settlement?date=YYYY-MM-DD` (운영 권한). 멱등하므로 여러 번 실행해도 안전
- **실패 건 재처리**: `POST /internal/batch/settlement/retry` - `tb_batch_failure`에서 `resolved_at is null` 대상
- **알림**: 실패 시 <채널>, 03:00까지 성공 로그 없으면 미실행 알람
- **관련 문서**: `docs/<도메인>/정산-비즈니스로직.md`

## 점검 규칙

- 새 배치를 추가하면 요약 표와 상세 절을 함께 추가한다.
- cron이나 프로퍼티 키가 바뀌면 이 문서가 진실이 되도록 먼저 고친다.
- 배치를 삭제하면 표에서 지우지 말고 "폐기(YYYY-MM-DD)"로 표시한 뒤 다음 정리 때 제거한다.
