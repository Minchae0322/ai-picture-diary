# UI 기본 원칙 (ui-fundamentals)

## 목적

"어느 정도가 맞는지" 매번 감으로 정하지 않기 위한 기본서. 여기 있는 것은 **스타일과 무관하게 항상 맞는 규칙**이다. 소프트 모던이든 브루탈리즘이든 중첩 라운드 계산법과 대비 기준은 같다. 구체적인 값(어떤 회색, 라운드 12px vs 4px)은 `design-system` 스킬의 프리셋이 정한다.

## 언제 적용

새 화면/컴포넌트 작성, 기존 UI 수정, "간격이 어색하다"·"뭔가 촌스럽다"는 피드백 처리, 디자인 시안을 코드로 옮길 때, 퍼블리싱 리뷰.

> **React Native / Expo라면** 이 스킬을 먼저 읽고, `expo-app-conventions`에서 달라지는 절만 덮어쓴다. 순서를 뒤집지 않는다.

## 0. 값을 정하는 순서

1. 프로젝트에 토큰(CSS 변수/Tailwind config)이 있으면 **거기서 고른다.** 새 값을 만들지 않는다.
2. 없으면 `design-system` 스킬로 토큰부터 세운다.
3. 토큰에 없는 값이 꼭 필요하면 왜 필요한지 한 줄로 설명하고 토큰에 추가한다. 일회용 매직 넘버 금지.

## 1. 스페이싱

- 4px 배수 스케일만 쓴다(4, 8, 12, 16, 24, 32, 48, 64). 6px, 13px, 17px 같은 값은 만들지 않는다.
- **여백은 관계를 말한다.** 가까울수록 한 덩어리. 라벨-입력창(8) < 필드-필드(24) < 섹션(48). 순서가 뒤집히면 그룹이 잘못 읽힌다.
- 요소 사이 간격은 부모의 안쪽 여백 이하로. 카드 padding 24면 카드 안 항목 간격은 24 이하.
- 간격은 부모의 `gap`으로 준다. 마지막 항목 `margin`을 지우는 코드가 있으면 `gap`으로 바꾼다. margin을 쓸 거면 한 방향으로만.

## 2. 라운드(모서리)

- **중첩 라운드 공식: 안쪽 반경 = 바깥 반경 - 그 사이 여백.** 카드 radius 16, padding 8이면 안쪽 요소는 8. 이걸 안 지키면 두 곡선이 어긋나 어색해 보인다.
- 계산값이 0 이하면 안쪽은 `0`. 여백이 바깥 반경의 2배 이상으로 크면 곡선이 서로 영향을 주지 않으므로 안쪽을 독립적으로 정해도 된다.
- 요소가 클수록 반경도 커진다: 버튼/입력창 < 카드 < 모달/시트. 전부 같은 값을 쓰면 큰 요소가 각져 보인다.
- 원형은 `border-radius: 9999px`. `50%`는 정사각형이 아닐 때 타원이 된다.
- 한 화면에서 라운드 값은 3~4단계 이내. 스케일도 토큰으로 관리한다.

## 3. 시각 계층

- 강조 수단(크기, 굵기, 색, 여백, 배경)을 **한 요소에 2개까지만.** 크고 굵고 빨갛고 배경까지 있으면 강조가 아니라 소음이다.
- 한 화면에 주 행동(primary) 버튼은 하나. 계층은 제목/본문/보조 3단계면 충분하고, 그 이상은 크기 대신 색 명도로 구분한다.
- 중요한 것을 크게 만들기 전에 **덜 중요한 것을 작고 흐리게** 해본다. 대부분 그게 답이다.

## 4. 타이포그래피

- 폰트 크기는 스케일에서 고른다(12, 14, 16, 20, 24, 32, 40). 본문은 14~16 이상.
- 줄간격: 본문 1.5~1.7, 제목 1.2~1.3. 글자가 클수록 줄간격 배수는 작아진다.
- 한 줄 길이는 45~75자. 넓은 화면에서 본문 컨테이너에 `max-width`를 준다.
- 굵기는 2~3종만(400/600/700). 100 단위로 촘촘히 쓰지 않는다.
- 자간은 큰 제목에만 살짝 좁힌다(-0.02em 내외). 본문 자간은 건드리지 않는다. 숫자를 세로로 비교하면 `font-variant-numeric: tabular-nums`.
- 한글은 영문보다 시각적으로 작게 보인다. 영문 기준 스케일을 그대로 쓰면 1~2px 키우는 편이 낫다.

## 5. 색

- 색은 **의미 이름**으로 쓴다: `surface`, `text-muted`, `border`, `danger`. `gray-300`을 컴포넌트에 직접 쓰지 않는다.
- 대비 기준(WCAG 2.2 AA): 본문 텍스트 4.5:1, 큰 텍스트(18.66px+ 또는 굵은 14px+) 3:1, UI 컴포넌트·아이콘 경계 3:1. **정하기 전에 계산한다.**
- 흐린 회색 본문(`#999`)은 대부분 대비 미달이다. 보조 텍스트도 4.5:1을 넘겨야 한다.
- **색만으로 정보를 전달하지 않는다.** 상태는 색 + 아이콘/텍스트.
- 중립 회색에 브랜드 색조를 아주 조금 섞으면 화면이 통일돼 보인다(순수 무채색보다 자연스럽다).
- 배경 위에 배경을 겹칠 때는 명도 차이를 최소 한 단계 두거나 테두리로 구분한다. 둘 다 없으면 안 보인다.

## 6. 그림자와 깊이

- 광원은 하나, 위에서. 모든 그림자의 y 오프셋은 양수, x는 0에 가깝게.
- 요소가 떠 있을수록 **흐림 반경이 커지고 불투명도는 낮아진다.** 진한 그림자를 크게 키우면 더러워 보인다.
- 자연스러운 그림자는 두 겹이다: 짧고 진한 것(접촉) + 길고 옅은 것(확산). 색은 검정 알파보다 **배경 색조를 섞은 어두운 색**이 낫다.
- 고도 단계는 3~4개로 제한(카드 / 드롭다운 / 모달), 값은 토큰으로. 깊이는 배경 명도 차이·테두리·겹침으로도 표현된다. 그림자만 쌓지 않는다.

## 7. 테두리와 구분선

- 구분선을 넣기 전에 **여백으로 먼저 나눠본다.** 대부분 선이 필요 없다. 테두리와 그림자를 같은 요소에 동시에 쓰지 않는다.
- 테두리 색은 배경보다 살짝 어두운 정도. 목록 구분선은 항목 사이에만, 첫 줄 위와 마지막 줄 아래에는 넣지 않는다.

## 8. 정렬

- 축을 만든다. 왼쪽 기준선이 여러 개면 화면이 흔들려 보인다.
- **광학 정렬**: 삼각형·재생 아이콘, 원형 아바타 옆 텍스트는 수학적 중앙이 시각적 중앙과 다르다. 눈으로 맞춘다.
- 아이콘과 텍스트를 나란히 둘 때는 `align-items: center` + 아이콘 크기를 텍스트 줄높이에 맞춘다.
- 숫자는 오른쪽, 텍스트는 왼쪽 정렬. 가운데 정렬은 짧은 한두 줄에만. 안쪽 여백은 상하좌우가 같을 필요 없다. 시각적으로 같아 보이는 값이 맞다.

## 9. 상태

- 인터랙티브 요소는 **5가지 상태를 모두 정의한다**: default / hover / focus-visible / active / disabled. 하나라도 빠지면 미완성.
- `outline: none`만 쓰고 끝내지 않는다. `:focus-visible`에 반드시 보이는 표시를 준다. 키보드 사용자에게는 이게 유일한 위치 단서다.
- hover는 터치 기기에 없다. hover에만 있는 기능을 만들지 않는다.
- disabled는 대비를 낮추되 **왜 비활성인지** 알 수 있게 한다. 선택/활성 상태는 색만으로 표시하지 않는다(테두리·굵기·아이콘 병행).

## 10. 크기와 터치 타깃

- 클릭 대상 최소 24x24 CSS px(WCAG 2.2 SC 2.5.8, AA). 모바일 주요 버튼은 44~48px 권장.
- 시각적으로 작은 아이콘 버튼은 padding이나 가상 요소로 **적중 영역만** 키운다.
- 인접한 타깃 사이에 최소 8px 간격. 오탭이 나는 UI는 대비보다 먼저 고쳐야 한다.

## 11. 반응형 (기본 구조)

- **반응형은 옵션이 아니라 기본 구조다.** 고정 폭으로 만들고 나중에 미디어 쿼리를 덧대는 순서로 하지 않는다.
- 주 타깃(모바일 우선 / 데스크톱 우선)을 먼저 정하고 `CLAUDE.md`에 적는다. 이 선택이 브레이크포인트 방향(`min-width` vs `max-width`)과 기본값을 결정한다(`design-system` 0장).
- **브레이크포인트는 기기 이름이 아니라 레이아웃이 깨지는 지점**에서 잡는다. 화면을 늘려보고 어색해지는 폭이 브레이크포인트다.
- 미디어 쿼리 전에 내재적 반응형을 먼저 시도한다: `flex-wrap`, `repeat(auto-fit, minmax(280px, 1fr))`, `clamp()`, `max-width` + `margin: auto`. 대부분 이걸로 끝난다.
- 컨테이너 폭에 반응해야 하는 컴포넌트(카드, 위젯)는 화면 폭이 아니라 컨테이너 쿼리(`@container`)를 쓴다.
- 폭 단위는 `%`, `fr`, `minmax`, `clamp`. 고정 `px`는 아이콘·아바타처럼 진짜 고정인 것만.
- 터치와 마우스를 둘 다 가정한다. hover 전용 기능 금지, 타깃은 터치 기준(10장). 안전 영역은 `env(safe-area-inset-*)`로 처리.
- 표와 코드 블록은 가로 스크롤 컨테이너에 넣는다. **본문이 가로로 스크롤되게 두지 않는다.** 텍스트 `clamp()`에는 상한을 둔다.

## 12. 모션

- 대부분 150~250ms. 큰 요소일수록 느리게, 300ms를 넘기면 느리게 느껴진다. 사용자 입력에 대한 반응은 100ms 이내에 시작한다.
- 나타날 때는 감속(ease-out), 사라질 때는 가속(ease-in). 왕복은 ease-in-out.
- `transform`과 `opacity`만 애니메이션한다. `width`/`top` 애니메이션은 렉을 만든다.
- **`prefers-reduced-motion: reduce`를 반드시 처리한다.** 큰 이동과 패럴랙스는 없애고 페이드만 남긴다.

## 13. 빈 상태 / 로딩 / 에러

- 데이터를 보여주는 화면은 **네 가지를 다 설계한다**: 로딩, 비어 있음, 에러, 정상. 정상만 만들면 나머지는 깨진 화면이 된다.
- 빈 상태에는 다음 행동을 넣는다. "데이터가 없습니다"만 있으면 막다른 길이다. 로딩은 레이아웃이 튀지 않게(스켈레톤 또는 고정 높이).
- 에러는 무슨 일이 났는지 + 무엇을 하면 되는지. 스택 트레이스나 코드만 노출하지 않는다.

## 리뷰 체크

- 스케일에 없는 값(13px, 6px, `#3a3a3a`)이 하드코딩돼 있는가, 중첩 라운드가 공식대로인가
- 대비가 4.5:1(본문) / 3:1(UI)을 넘는가, 색만으로 정보를 전달하지 않는가
- focus-visible 표시가 있는가, 상태 5종이 정의됐는가
- 클릭 대상이 24px 이상이고 인접 타깃 간격이 있는가
- 로딩/빈 상태/에러 화면과 `prefers-reduced-motion` 처리가 있는가
- 좁은 폭과 넓은 폭에서 모두 확인했는가, 본문이 가로로 스크롤되지 않는가

## 하지 말 것

- 토큰 없이 매직 넘버 하드코딩
- 중첩 라운드에서 바깥과 안쪽에 같은 값 주기
- `outline: none`만 하고 focus 표시 없애기
- 흐린 회색 본문(대비 미달)
- 한 요소에 강조 수단 3개 이상, 한 화면에 primary 버튼 여러 개
- 테두리 + 그림자 동시 사용, 그림자만 쌓아 깊이 표현
- 정상 화면만 만들고 로딩/빈/에러 빼먹기
- 고정 폭으로 만들고 나중에 미디어 쿼리 덧대기, 기기 이름으로 브레이크포인트 잡기
- 색만으로 상태 구분

## 관련 스킬

`design-system`(토큰 체계와 스타일 프리셋 - 구체적인 값은 여기서), `figma-workflow`(시안에 없는 것을 이 문서로 채운다), `api-design`(에러 응답을 화면 에러 문구로 옮길 때).
