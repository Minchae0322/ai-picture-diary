# 개조식 보고 문체 (report-style)

## 목적
같은 사실을 절반 길이로, 더 정확하게 쓴다. 읽는 사람은 문장을 감상하지 않고 **사실을 찾는다.** 배경 설명·접속사·수식어는 찾는 일을 방해한다.

## 언제 적용
특이사항·이슈·동향 정리, 주간/월간 보고, 회의록, 장애 보고서 요약, 산출물 문서의 요약 절. **적용하지 않는 곳**: 사용자에게 보이는 문구, 이메일 본문, 설명을 목적으로 하는 가이드 문서. 이 스킬은 **보고용**이다.

## 0. 쓰기 전에 - 용어집을 먼저 연다

이 스킬의 문체 규칙은 **분야와 무관하다.** 분야 용어만 `glossary/<분야>.md`에 따로 있다.

- 해당 분야 파일이 있으면 읽고 4장에서 치환한다.
- **없으면 만들지 말고** 원문 표현을 그대로 두고 `(용어 확인 필요)`를 붙인다. 잘못된 업계 용어는 풀어 쓴 말보다 나쁘다.
- 분야 파일이 반복해서 필요해지면 그때 `glossary/README.md`의 절차로 추가한다.

현재 `glossary/`에 있는 파일은 **작성 예시**다. 이 스킬이 그 분야 전용이라는 뜻이 아니다.

## 1. 종결어미 - 명사형/음슴체

| 원문 | 고침 |
|---|---|
| 끝났습니다 / 끝났다 | 종료됨, 종료 |
| 유예했습니다 | 유예함 |
| 늘어날 것으로 보입니다 | 증가 예상됨 |
| 검토 중입니다 | 검토 중 |
| 확인이 필요합니다 | 확인 필요 |

- **한 문장에 한 사실.** 두 사실이면 두 줄로 나눈다.
- 문장 끝 마침표는 찍는다. 붙였다 말았다 하지 않는다.
- 명사로 끝낼 수 있으면 명사로 끝낸다(`검토 중`이 `검토 중임`보다 짧다).

## 2. 사실과 추정을 종결어미로 구분한다

이 구분이 이 문체의 핵심이다. 흐리면 보고서가 아니라 소설이 된다.

| 종류 | 종결 | 예 |
|---|---|---|
| 확인된 사실 | `~함`, `~됨`, `~임` | IRA가 PSS를 유예함 |
| 예상·전망 | `~예상됨`, `~전망` | 물동량 회복 예상됨 |
| 미확정·확인 필요 | `~(확인 필요)`, `~검토 중` | 적용 시점 미정(확인 필요) |

**원문에 없는 정보를 채워 넣지 않는다.** 기간·수치를 보강했으면 근거가 있어야 하고, 없으면 `(확인 필요)`를 붙인다.

## 3. 접속사를 지우고 인과를 문장 안으로

| 원문 | 고침 |
|---|---|
| A가 끝났습니다. **따라서** B가 늘어날 것입니다 | A 종료**에 따라** B 증가 예상됨 |
| A입니다. **그러나** B입니다 | A이나 B (또는 두 줄로 분리) |
| **또한** C했습니다 | C함 (접속사 삭제, 줄만 바꿈) |

`따라서 / 또한 / 그리고 / 그래서 / 한편`은 거의 항상 지운다. 순서가 곧 흐름이다.

## 4. 풀어 쓴 말을 업계 용어로

용어집에 있으면 반드시 치환한다. 짧아지는 게 아니라 **정확해진다.**

아래는 `glossary/해운-물류.md`를 쓸 때의 예다. 분야가 다르면 그 분야 파일을 본다.

| 풀어 쓴 말 | 용어 |
|---|---|
| 실제 적재 비율 | 소석률 |
| 거래량, 화물량 | 물동량 |
| 성수기 할증료 | PSS |
| 선사협의체 | (해당 협의체 고유명. 중동항로면 IRA) |

## 5. 약어와 수치 표기

- **약어는 첫 등장에만 병기**한다: `PSS(성수기할증료)`. 같은 문서 안에서 두 번 병기하지 않는다.
- 이미 그 문서의 독자가 다 아는 약어는 병기하지 않는다. 판단이 서면 묻는다.
- 통화는 ISO 코드 + 단위: `USD 300/TEU`. `컨테이너당 300달러`, `$300`, `300불` 모두 쓰지 않는다.
- 비율은 `%`, 증감은 부호나 방향어를 붙인다: `소석률 95%`, `전월 대비 +3%p`.
- 날짜는 `YYYY.M.D`, 기간은 `~`. **연도를 생략할 거면 양쪽 다 생략한다**: `2012.7.20~8.18` (O) / `2012.7.20~12.8.18` (X - 뒤쪽이 연도인지 월인지 읽히지 않는다).
- 고유명사 뒤 괄호에 기간·수치를 붙여 한 줄로 만든다: `라마단(2012.7.20~8.18) 종료에 따라`.

## 6. 지울 것 / 남길 것

| 지운다 | 예 |
|---|---|
| 배경·상식 설명 | "이슬람 최대 명절 중 하나인" |
| 주관적 수식어 | "크게", "매우", "급격히" (수치가 있으면 수치만) |
| 본문에서 파생되는 부연 | 앞 문장에서 이미 읽히는 괄호 설명 |
| 화자 표시 | "~라고 판단됩니다", "제 생각에는" |

| 남긴다 |
|---|
| 날짜·기간 |
| 금액·수량·비율 (단위 포함) |
| 행위 주체 (누가 했는가) |
| 상태 변화 (전 → 후) |
| 미확정이라는 사실 자체 |

숫자를 지워야 할지 애매하면 남긴다. 배경 설명은 애매하면 지운다.

## 7. 구조

```
<대상> 관련 이슈          <- 제목 한 줄. "관련 이슈" / "동향" / "특이사항"
<사실 1>.
<사실 2>.
```

- 항목이 5줄을 넘으면 소제목으로 묶는다.
- 제목에 날짜를 넣지 않는다. 문서 상단 메타에 둔다.
- 불릿 기호(`-`)는 항목이 3개 이상일 때만. 2줄짜리에 불릿을 달면 형식이 내용보다 커진다.

## 8. 고칠 때의 순서

원문을 고칠 때는 이 순서로 한다. 순서를 섞으면 지운 것을 다시 쓰게 된다.

1. 사실만 뽑는다 (6장의 "남긴다")
2. 용어를 치환한다 (0장, 4장)
3. 수치·날짜 표기를 정규화한다 (5장)
4. 종결어미를 맞춘다 (1장, 2장)
5. 접속사를 지운다 (3장)
6. **원문과 대조한다** - 사라진 사실이 있는지, 없던 사실이 생겼는지

6번을 건너뛰지 않는다. 요약에서 가장 흔한 사고는 짧아진 게 아니라 **틀려진 것**이다.

## 하지 말 것

- 확인 안 된 것을 단정형(`~함`)으로 쓰기
- 원문에 없는 날짜·수치를 근거 없이 채워 넣기
- 용어집에 없는 약어를 짐작해서 쓰기
- 존댓말과 개조식을 한 문서에서 섞기
- 정확성을 잃으면서까지 줄이기 - 두 줄이 맞으면 두 줄로 쓴다
