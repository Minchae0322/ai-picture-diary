# 화면 05~10 API 명세 (캘린더 · 그래프 · 뱃지 · 커뮤니티 · 프로필/꾸미기)

> 2026-09-22 · 프론트 전달용 · 핵심 루프(02~04)는 `2026-09-21-일기-API-명세.md`

## 공통

공통 규약(봉투·인증 헤더·커서·ID 문자열)은 일기 API 명세와 같다. 여기서는 **다른 점만** 적는다.

- 화면 10의 통계 3종은 한 엔드포인트가 아니다. `GET /api/v1/diaries/overview`(총 기록·연속)와
  `GET /api/v1/badges`(뱃지 수)를 앱이 함께 부른다. 도메인을 서버에서 억지로 합치지 않았다.
- **연속 기록 일수는 `/diaries/overview`와 `/diaries/stats`가 같은 계산(StreakCalculator)을 쓴다.** 02·06·10이 같은 값을 본다.

### 추가 에러 코드

| code | HTTP | 언제 |
|---|---|---|
| `DIARY_NOT_DONE` | 422 | 아직 그리는 중이거나 실패한 일기를 공유하려 함 |
| `POST_NOT_FOUND` | 404 | 없거나 이미 지워진 게시글 |
| `POST_ALREADY_SHARED` | 409 | 같은 일기를 두 번 공유 |
| `POST_ALREADY_REPORTED` | 409 | 같은 글을 두 번 신고 |
| `STORE_ITEM_NOT_FOUND` | 404 | 없는 아이템 코드 |
| `STORE_ITEM_LOCKED` | 422 | Jelly Plus 전용 아이템을 비구독자가 선택 |

## 05 감정 캘린더

### GET /api/v1/diaries/calendar

| 쿼리 | 기본 | 설명 |
|---|---|---|
| `month` | 서버 기준 이번 달 | `YYYY-MM` |

```json
{
  "data": {
    "month": "2026-08",
    "days": [
      { "date": "2026-08-23", "diaryId": "11", "weather": "SUNNY", "moodScore": 2 }
    ],
    "summary": [ { "weather": "SUNNY", "days": 12 }, { "weather": "RAIN", "days": 4 } ],
    "recordedDays": 24
  },
  "meta": { "traceId": "..." }
}
```

- `days`에는 **기록이 있는 날만** 들어온다. 빈 칸은 앱이 날짜로 채운다.
- `summary`는 서버가 계산한다. 앱이 다시 세면 06 그래프와 값이 갈린다.
- `recordedDays`가 0이면 그 달은 기록이 없다 -> 요약 자리에 빈 상태 문구.

## 06 감정 그래프

### GET /api/v1/diaries/stats

| 쿼리 | 기본 | 설명 |
|---|---|---|
| `period` | `MONTH` | `WEEK`(7일) / `MONTH`(30일) / `YEAR`(365일). 오늘을 포함한 N일 |

```json
{
  "data": {
    "period": "MONTH",
    "from": "2026-07-26",
    "to": "2026-08-24",
    "points": [ { "date": "2026-08-01", "moodScore": 2 } ],
    "average": 1.2,
    "previousAverage": 0.8,
    "bestDate": "2026-08-19",
    "bestScore": 3,
    "streakDays": 14,
    "recordedDays": 21,
    "words": [ { "word": "회의", "count": 7 } ]
  },
  "meta": { "traceId": "..." }
}
```

- **무기록일은 `points`에 없다.** 앱은 날짜가 연속하지 않는 지점에서 선을 끊는다. 0으로 채우지 않는다 - 0은 "보통"이라는 뜻이라 거짓이 된다.
- `average`는 기록이 있는 날만의 평균이며 소수 첫째 자리 반올림. 기록이 없으면 `null`.
- `previousAverage`는 바로 앞의 같은 길이 기간. 없으면 `null`이고 앱은 비교 문구를 생략한다.
- `words`는 공백 토크나이저 + 조사 제거로 뽑은 상위 4개다. 형태소 분석기가 아니다.

## 07 뱃지

### GET /api/v1/badges

```json
{
  "data": {
    "badges": [
      { "code": "FIRST_RECORD", "name": "첫 기록", "condition": "1일", "earned": true, "earnedAt": "2026-03-02T12:00:00Z" },
      { "code": "RAINBOW_30", "name": "무지개 30", "condition": "30일 연속", "earned": false, "earnedAt": null }
    ],
    "earnedCount": 5,
    "totalCount": 12
  },
  "meta": { "traceId": "..." }
}
```

- 정의된 뱃지는 **잠금 상태로도 전부** 내려온다. 빈 화면이 생기지 않는다.
- 조건 문구(`condition`)도 서버가 준다. 정의는 `tb_badge` 마스터 테이블이라 뱃지를 늘려도 앱 배포가 없다.
- 배열 순서가 07 그리드 순서다(`tb_badge.sort_order`). 앱이 따로 정렬하지 않는다.
- `totalCount`는 **지금 정의된 수**(tb_badge 행 수)다. 시안의 "40개" 중 28개는 아직 정의되지 않았다.
- `code` 는 `tb_badge.code`. 앱이 코드로 분기하지 않는다 - 이름·문구는 서버가 준 값을 그대로 보여준다.
- 획득 판정은 서버가 일기 저장 성공 직후에 한다. 앱은 `earnedAt`이 오늘인 뱃지를 04 화면의 획득 카드로 보여줄 뿐이다.

## 08 커뮤니티

### GET /api/v1/community/posts

| 쿼리 | 기본 | 설명 |
|---|---|---|
| `sort` | `RECOMMENDED` | `RECOMMENDED` / `LATEST` / `POPULAR` |
| `weather` | 없음(전체) | 다중. `?weather=SUNNY&weather=RAIN` |
| `cursor` | 없음 | 이전 응답의 `meta.nextCursor` |
| `size` | 20 | 최대 50 |

```json
{
  "data": [
    {
      "id": "31",
      "authorName": "복숭아젤리",
      "weather": "RAIN",
      "content": "비 오는 날 창가에서 커피 한 잔",
      "likeCount": 128,
      "commentCount": 14,
      "likedByMe": false,
      "mine": false,
      "createdAt": "2026-08-24T05:12:00Z"
    }
  ],
  "meta": { "traceId": "...", "nextCursor": "TEFURVNUOjMx", "hasNext": true }
}
```

### 정렬 3종

| 값 | 무엇 | 커서 키 |
|---|---|---|
| `RECOMMENDED` | 내 오늘 기분과 비슷한 글 먼저 | (추천 점수, id) |
| `LATEST` | 최신순 | (id) |
| `POPULAR` | 좋아요 누적순. 시간 감쇠 없음 | (좋아요 수, id) |

추천 점수는 **날씨 일치 2점 + 기분 점수 1칸 이내 1점 + 최근 3일 1점**(0~4점). 동점이 많아 뒤에 id가 붙는다.
기준("내 오늘")은 요청 시작에 한 번 읽어 페이지 내내 고정된다.

**다양성**: 추천 정렬에서 상위 10개 중 2개는 내 날씨와 다른 글이 오도록 순서를 바꾼다.
페이지에 담기는 글 목록 자체는 바뀌지 않으므로 커서는 영향받지 않는다.
`weather` 필터를 직접 건 요청에는 적용되지 않는다.

> [!IMPORTANT]
> **오늘 기록이 없으면 `RECOMMENDED`는 조용히 `LATEST`로 동작한다.** 에러가 아니다.
> 앱은 오늘 기록 유무를 이미 알고 있으므로 그 사실로 안내 문구를 띄운다.

- **커서는 정렬마다 다르다.** 정렬을 바꾸면 이전 커서는 400 `COMMON_INVALID_CURSOR`가 된다. 앱은 정렬 변경 시 처음부터 다시 읽는다.
- 상대 시각("2시간 전")은 앱이 `createdAt`으로 만든다.
- `weather`는 문자열이다. 값 목록은 일기의 `Weather`와 같다.

### POST /api/v1/community/posts - 04 "공유"

| 요청 필드 | 타입 | 필수 |
|---|---|---|
| `diaryId` | string | O |

본문·날씨·작성자명은 **서버가 일기와 프로필에서 복사한다.** 클라이언트가 보내지 않는다(위변조 지점을 만들지 않는다).

성공 **201** + `Location` / `{ "data": { "id": "31" } }`
에러: 422 `DIARY_NOT_DONE`, 409 `POST_ALREADY_SHARED`, 404 `DIARY_NOT_FOUND`

### POST / DELETE /api/v1/community/posts/{id}/like

바디 없음. 성공 **204**. **멱등이다** - 이미 누른 상태로 다시 POST해도 204이고 수치는 변하지 않는다.
앱은 낙관적 업데이트 후 실패 시 되돌린다.

### POST /api/v1/community/posts/{id}/report

| 요청 필드 | 타입 | 필수 |
|---|---|---|
| `reason` | `ABUSE` \| `SPAM` \| `SEXUAL` \| `PRIVACY` \| `OTHER` | O |
| `detail` | string(≤200) | X |

성공 **204**. 에러: 409 `POST_ALREADY_REPORTED`
시안에 없지만 UGC 배포의 필수 동선이다(`app-store-release`).

### DELETE /api/v1/community/posts/{id}

내 글만 지운다. 남의 글은 404로 감춘다. 성공 **204**.

## 09·10 프로필 / 꾸미기

### GET /api/v1/profile

```json
{
  "data": {
    "nickname": "말랑한 젤리곰",
    "themeCode": "JELLY", "themeName": "Jelly",
    "characterCode": "JELLY_BEAR", "characterName": "젤리곰",
    "plus": false,
    "joinedOn": "2026-03-02",
    "reminderTime": null,
    "aiStyle": "수채화",
    "diaryLock": false
  },
  "meta": { "traceId": "..." }
}
```

인증이 없어 프로필 행이 미리 없다. **첫 조회에서 기본값으로 만들어 준다.** 회원가입이 붙으면 그쪽으로 옮긴다.
닉네임은 "형용사 + 명사"로 무작위 생성된다(중복 가능). 그림 스타일 초깃값과 닉네임 길이 상한은 `app.profile.*` 설정이다.

### PATCH /api/v1/profile/settings

보낸 필드만 바꾼다. `reminderTime`을 `null`로 보내면 "설정 안 함"이다.

| 필드 | 타입 |
|---|---|
| `nickname` | string. 상한은 `app.profile.max-nickname-length`(현재 30) |
| `reminderTime` | `HH:mm:ss` 또는 null |
| `aiStyle` | string(≤40) |
| `diaryLock` | boolean |

응답은 `GET /api/v1/profile`과 같다.

### GET /api/v1/profile/store/items

```json
{
  "data": [
    { "code": "JELLY", "category": "THEME", "name": "Jelly", "description": "기본",
      "plusOnly": false, "locked": false, "selected": true },
    { "code": "NIGHT_JELLY", "category": "THEME", "name": "Night Jelly", "description": "밤의 젤리",
      "plusOnly": true, "locked": true, "selected": false }
  ],
  "meta": { "traceId": "..." }
}
```

- `locked`는 **서버가 구독 상태를 보고 정한다.** 클라이언트 플래그를 신뢰하지 않는다.
- `category`는 `THEME` / `CHARACTER`. 시안의 배경·폰트 탭은 항목이 없어 내려오지 않는다 -> 앱은 탭 자체를 숨긴다.

### POST /api/v1/profile/store/items/{code}/select

바디 없음. 응답은 `GET /api/v1/profile`과 같다.
에러: 422 `STORE_ITEM_LOCKED`(구독 필요), 404 `STORE_ITEM_NOT_FOUND`
