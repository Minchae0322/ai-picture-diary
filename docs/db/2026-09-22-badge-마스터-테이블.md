# 2026-09-22 뱃지 마스터 테이블 추가

> 2026-09-22 · DB 변경 · SQL `sql/patch/2026-09-22-badge-마스터-테이블.sql`
> 같은 날 `2026-09-22-badge-community-profile-테이블-추가.sql` 다음에 실행한다

## 무엇을
- `tb_badge` + `seq_badge` 추가. 시안 12종을 seed 로 넣는다.
- `tb_user_badge.badge_type` -> `badge_code` 로 이름 변경(인덱스 이름도 함께).

## 왜
뱃지 정의를 코드 enum(`BadgeType`)에서 테이블로 옮겼다.

- 시안이 말한 **40종** 중 12종만 정해졌다. 나머지를 채울 때마다 배포하고 싶지 않다.
- 07 화면 문서 6장이 "조건 문구도 서버가 준다(앱 업데이트 없이 추가하기 위함)"를 요구한다.
- 조건이 전부 **`지표 >= 임계값`** 으로 환원된다. 그래서 규칙 엔진 없이 데이터로 표현된다.

### 코드와 데이터를 나눈 지점

| 무엇 | 어디 | 바꾸려면 |
|---|---|---|
| 이름, 조건 문구, 임계값, 정렬, 노출 | `tb_badge` | SQL |
| **무엇을 재는가**(`BadgeMetric`) | 코드 | 배포 |

"맑음 20회" 같은 뱃지는 INSERT 한 줄로 늘어난다. "댓글을 30일 안에 10개"처럼 **새로운 종류의 지표**가
필요하면 `BadgeMetric` 에 값을 더하고 `BadgeCriteria` 에 그 값을 채우는 자리를 만들어야 한다.

> [!WARNING]
> `metric` 에 코드에 없는 값을 넣으면 그 뱃지는 **조용히 영원히 안 걸린다.** 에러도 나지 않는다.
> seed 를 손으로 고칠 때 `BadgeMetric` 목록을 먼저 본다.

## 영향
- 신규 테이블 + 컬럼 이름 변경. `tb_user_badge` 에 데이터가 있으면 이름만 바뀌고 값은 그대로다(enum 이름과 code 가 같다).
- 애플리케이션은 `ddl-auto: validate` 라 이 SQL 이 먼저 실행돼야 기동된다.
- FK 를 걸지 않았다. 정의를 내려도(soft delete) 이미 받은 기록은 남아야 한다. 대신 화면에서 사라진다.
