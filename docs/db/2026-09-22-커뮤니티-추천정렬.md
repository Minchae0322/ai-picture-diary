# 2026-09-22 커뮤니티 추천 정렬용 컬럼 추가

> 2026-09-22 · DB 변경 · SQL `sql/patch/2026-09-22-커뮤니티-추천정렬.sql`
> 선행: `2026-09-22-badge-community-profile-테이블-추가.sql`

## 무엇을
`tb_community_post.mood_score` 추가(NOT NULL, -3~3 check)와 `ix_community_post_weather_id_desc` 인덱스.

## 왜
08 피드에 "추천" 정렬을 넣는다. 점수는 **날씨 일치 2 + 기분 점수 1칸 이내 1 + 최근 3일 1**이고,
앞의 둘을 재려면 게시글이 기분 점수를 들고 있어야 한다.

게시글은 일기의 **복사본**이라 원본을 되짚어 점수를 읽을 수 없다(원본이 지워질 수 있고, 조인이 매 정렬마다 붙는다).
공유 시점에 복사한다 - 날씨·본문·닉네임과 같은 이유다.

### 점수 컬럼을 만들지 않은 이유

추천 점수는 **보는 사람마다 다르다.** 미리 계산해 둘 수 없어서 매 요청 계산한다.
그래서 점수용 인덱스도 만들 수 없다. 대신 `(weather, id DESC)` 인덱스로 날씨 필터와 2차 정렬 키를 같이 태워
후보를 좁힌다.

> [!NOTE]
> 글이 많아지면 매 요청 전체 스캔이 문제가 된다. 그때는 후보를 N개로 자르고 그 안에서만 점수 정렬하는
> 방식(`feed-ranking` 2장의 "첫 페이지만 개인화")으로 바꾼다. 지금 글 수는 0이다.

## 영향
- 기존 행은 `tb_diary` 에서 점수를 채운 뒤 NOT NULL 로 바꾼다. 지금은 데이터가 0건이라 사실상 무영향.
- 원본 일기가 이미 지워진 행은 중립값 0으로 채운다.
- 애플리케이션은 `ddl-auto: validate` 라 이 SQL 이 먼저 실행돼야 기동된다.
