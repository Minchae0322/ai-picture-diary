## 4. 동작
- `dots`가 3개 = 슬라이드 3장 전제. 2·3번째 슬라이드는 시안에 없음(**미정**).
- 좌우 스와이프로 슬라이드 이동, 마지막 슬라이드에서만 CTA 활성화 여부는 미정 -> 기본은 **모든 슬라이드에서 CTA 노출**.
- 보조 링크는 텍스트 버튼. 터치 타깃 44px 확보(`ui-fundamentals`).

## 8. 구현 (2026-09-21)

- 화면: `app/app/onboarding.tsx`. 탭바 없음. `app/app/(tabs)/_layout.tsx`가 완료 플래그를 보고 여기로 보낸다
- **히어로를 손그림 로고로 바꿨다(의도된 시안 이탈).** 시안의 `jelly-bowl`(꽃잎 + 젤리)은 쓰지 않는다
  - 투명 배경 PNG(2048x2048 RGBA)라 하늘 그라디언트 위에 그대로 얹힌다
  - 원본 2048 안에서 실제 그림은 x 381~1739, y 317~1589이다(알파 경계 상자 측정값).
    가로의 34%가 투명 여백이고 중심도 오른쪽으로 36px 치우쳐 있어 PNG를 그냥 가운데 두면 그림은 가운데가 아니다
  - **그림 영역을 레이아웃 박스로 삼고** 그 안에 원본을 밀어 넣는다. 투명 여백만 잘리고 보이는 것은 잘리지 않는다
  - 그림 표시 폭 280. 크기는 `--art-w`(HTML) / `ART_WIDTH`(RN) 한 곳만 고친다
  - 히어로 자리(`.hero-slot`, RN은 `styles.hero`)는 좌우 -45로 화면 여백을 상쇄해 폰 폭을 다 쓴다.
    이게 없으면 그림이 300px 칼럼보다 넓어질 때 flex의 auto 마진이 0으로 풀려 왼쪽에 붙고 오른쪽만 잘린다
  - **움직임 없음.** 한때 구름 3장이 떠다녔으나 로고로 바뀌며 모션을 뺐다
  - 폭과 그림이 `app/src/features/onboarding/ui/OnboardingHero.tsx` 와 `docs/screen/prototype.html` 에 같은 값으로 있다. **한쪽만 고치지 않는다**
  - 같은 파일이 `app/assets/images/` 와 `docs/screen/images/` 에 두 벌 있다(앱용·문서용). 1.8MB짜리라 줄일 여지가 있다
- 에셋: `app/assets/images/onboarding.png`(히어로), `bottom.png`(바닥 띠), `app/assets/figma/onboarding-dots.svg`(인디케이터),
  `sunlight.svg`(공통 배경). `jelly-bowl.svg` 는 이제 참조하는 곳이 없다 - 지워도 된다
- 플래그: `app/src/shared/lib/onboarding.ts` (`onboarding_done`, AsyncStorage). 읽는 동안은 화면을 그리지 않아 온보딩이 번쩍이지 않는다
- 시안의 844 고정 좌표를 위아래 여백으로 바꿔 어느 화면 높이에서도 순서가 유지된다
- **CTA "무료로 시작하기"는 반투명 유리다**(`glass-button` 스킬). 앱에서 유일한 유리 요소이며
  프리셋 예외로 기록돼 있다(`presets/muted-sky.md` 5.5장). 화면 바닥에는 손그림 대각선 띠
  `images/bottom.png` 가 깔린다(투명 배경 PNG, 위 47%가 비어 있어 잘라내지 않고 그대로 얹는다).
  이 띠가 유리가 흐릴 대상이다 - 지우면 유리가 그냥 반투명 면이 된다.
  얇은 선이라 유리의 blur 를 3px 로 낮춰야 선이 살아남는다(스킬 2번)
- **유리는 HTML 프로토타입에만 있다.** `backdrop-filter`·`mask-composite`가 RN에 없어
  `app/app/onboarding.tsx`는 아직 solid 버튼이다(7장)
- 문구를 시안에서 바꿨다. 헤드라인 "오늘의 기분을 날씨로 그려드릴게요" -> **"오늘의 기분을 나만의 그림일기로"**,
  서브카피 "AI가 감정을 읽고 / 날씨와 그림을" -> **"AI가 기분을 읽고 / 그림일기를"**
- 헤드라인의 "오늘의 기분"·"그림일기" 뒤에 **형광펜 띠**를 깔았다(`highlight` 토큰).
  띠는 `#7c5445`, 그 위 글자는 **배경과 같은 바닐라** `#faf4dc`(`highlight` / `highlightText` 토큰).
  글자가 파인 것처럼 보인다. 대비 5.93:1.
  **글자색이 배경과 같아 띠가 글자를 완전히 덮어야 한다** - 띠 밖으로 나간 획은 배경에 묻혀 사라진다. 띠가 어둡고 글자가 밝은 조합이라 다크에서도 같은 값이 그대로 통한다 - 다크용 값을 따로 두지 않는다
- **띠 높이는 글자 잉크에 맞춘다**(2026-09-28). 덮는 것이 조건이므로 **줄일 수 있는 바닥은 잉크 높이**다.
  - 세로 `padding` 으로는 못 줄인다. padding 은 더하기만 되고, 배경이 깔리는 인라인 박스는 이미
    폰트의 ascent+descent = (988+260)/1000 = **1.248em** 이다
  - 그래서 배경을 `linear-gradient` 로 그려 `background-size` 로 높이를 em 단위로 직접 준다
  - SUIT-Heavy 의 이 한글들 잉크는 **baseline 기준 -0.093em ~ 0.821em, 높이 0.914em**
    (CFF charstring 을 직접 읽어 잰 값. CID 폰트라 FDSelect/FDArray 로 글리프별 로컬 subr 을 찾아야 나온다)
  - 띠는 **-0.130em ~ 0.870em(1em)**. 위 1.7px / 아래 1.3px 여유를 남기고 획을 다 덮는다(34px 기준)
  - 결과: 띠 **45.2px -> 34px**, 위아래 줄 사이 틈 **4.2px -> 15.3px**
  - **RN 은 이 값을 따라오지 못한다.** 중첩 `Text` 의 `backgroundColor` 는 줄 높이를 따라 칠해져
    띠 높이를 따로 줄 수단이 없다(현재 약 49.3px). 맞추려면 띠를 측정된 글자 폭 위에 절대 배치한
    `View` 로 그려야 하는데 깨지기 쉬워 두지 않았다. **의도된 미해결 차이다**
- 히어로 뒤에 **노트 괘선**을 깔았다(`rule` 토큰 `rgba(63,63,63,.22)`, 32px 간격 1px, 좌우 28px 여백).
  양쪽 다 1px 요소를 간격대로 깐다(HTML `.rule-sheet > i`, RN `NotebookLines.tsx`).
  한때 HTML만 `repeating-linear-gradient` 한 줄로 그렸으나 **브라우저 리샘플링이 1px 선을 몇 줄씩 통째로 떨어뜨려** 실제 요소로 바꿨다.
  좌우 여백은 컨테이너 inset 28px 으로 낸다.
  다크에서는 어두운 배경에 묻혀 `rgba(255,255,255,0.12)` 로 바꾼다
- 아직: 슬라이드 2·3(시안에 없음), 로그인 화면. "이미 계정이 있어요"는 지금 홈으로 보낸다
- **미해결: "이미 계정이 있어요"의 대비**(2026-09-28 측정). 이 보조 링크는 바닥에서 56~100px 자리에 있고
  뒤로 `bottom.png` 의 가는 갈색 선이 지나간다. 선이 이 구간 픽셀의 **7%** 를 덮어,
  선이 글자를 가로지르는 자리에서 대비가 **1.0:1** 까지 떨어진다(실제 픽셀 측정).
  - **색만 바꿔서는 못 고친다.** 배경이 밝은 파랑과 진한 갈색 두 톤이라 어떤 단색도 한쪽에서 무너진다:
    `#4e6375` 1.06, `#253544` 2.13, 바닐라 1.33, 코코아 1.11 - 넷 다 4.5:1 실패
  - 글자만 남기기로 했으므로(디자인 결정), 남은 방법은 **띠를 링크 아래에서 끊는 것**이다.
    `.bottom-art` / `styles.bottomArt` 의 높이를 230 -> 150 으로 줄이면 링크가 바닐라 배경 위로 올라와
    현재 색 그대로 **5.66:1** 로 통과한다. 다만 띠 위치가 다시 내려앉는다
  - CTA 가 멀쩡한 이유는 유리의 `blur(3px)` 가 그 선을 녹이고 있기 때문이다
