# 02 홈 · 오늘 기록 전

> 시안: [8:28](https://www.figma.com/design/zbYEQIRk1ttPOFzojh2hcL/AI-%25EA%25B0%2590%25EC%25A0%2595-%25EB%2582%25A0%25EC%2594%25A8%25EC%259D%25BC%25EA%25B8%25B0---Web-App-Sketch?node-id=8-28) · 탭: 홈 · 갱신: 2026-10-20

## 1. 목적
오늘의 한 줄을 받는 화면. 이 앱의 핵심 입력 지점이다.

## 2. 진입 / 이탈
- 진입: 앱 실행 기본 화면, 탭바 "홈".
- 이탈: 기록 전송 -> 03 AI 생성 중 / 최근 기록 탭 -> 과거 상세(**미정**).
- 오늘 기록이 이미 있으면 이 화면 대신 **04 결과 화면**을 보여준다(시안에 "오늘 기록 전"이라 명시).

## 4. 동작

- **기분은 늘 하나가 골라져 있다**(기본값 `HAPPY`). 다른 것을 누르면 바뀌고 **해제되지 않는다** -
  "안 고른 상태"를 다루는 분기가 화면에서 사라졌다. 그래서 전송 조건은 **본문 하나**뿐이다.
  - **ADR 2026-10-20 과 어긋난다.** 그 ADR 의 근거는 "안 눌러도 되는 버튼은 안 눌린다"였는데,
    기본값을 두면 손대지 않은 사람은 전부 `HAPPY` 로 기록된다. 서버는 여전히 `userHint` 를
    요구하므로 막는 장치가 사라지는 것이 아니라 **늘 충족되는 것**이다. 바꾸려면 ADR 을 다시 쓴다.
- **안내 문구를 화면에 띄우지 않는다.** 무엇이 비었는지는 종이가 이미 보여 준다 -
  빈 괘선이 그것이다. 다만 **스크린리더에는 남긴다**(`accessibilityHint`).
- 본문 1~200자. 글자 수는 **줄을 먹지 않고** 오른쪽 아래에 떠 있다 - 한 줄로 두면 첫 괘선 위가
  통째로 비어 글이 둘째 줄부터 시작한다.
- **그림체는 프로필(`aiStyle`)에 저장된다.** 다음에 열어도 고른 것이 남아 있어야 하는 값이라
  화면이 들고 있지 않는다. 고르면 **바로 위 그림칸의 견본이 즉시 바뀐다** - 조작과 결과가 붙어 있다.
  - **아직 생성에 반영되지 않는다.** `DiaryPainter.paint()` 가 스타일을 받지 않는다.
- 공책은 다섯 줄로 시작해 일곱 줄까지 자란다.
- 키보드가 올라와도 쓰던 자리가 보이고, **키보드가 떠 있을 때의 첫 탭이 먹히지 않는다**
  (`Screen` 의 `automaticallyAdjustKeyboardInsets` + `keyboardShouldPersistTaps`).
- "오늘 그리기"를 누르면 즉시 03으로 전환. 낙관적 전환이며 실패 시 입력값을 복원한다.
- **04 에서 "다시 쓰기"로 돌아오면 지운 기록의 글·기분·그림을 들고 온다.** 빈 종이로 돌려보내면
  방금 쓴 글을 다시 치게 된다 - 고치려고 누른 것이지 지우려고 누른 것이 아니다.
- **최근 기록은 홈에서 뺐다**(2026-10-25). 홈이 하는 일은 하나다 - 오늘 한 편을 쓰고 그림을 받는 것.
  지난 기록은 05 캘린더가 그 일만 하는 탭으로 이미 있다.

## 5. 상태
- 로딩: 최초 진입 시 최근 기록·연속일 조회 -> 스켈레톤 3줄.
- 빈: 최근 기록 0건이면 섹션 자체를 숨긴다(빈 목록 노출 금지). 연속 0일이면 배지 숨김.
- 에러: 조회 실패해도 **입력은 살려 둔다**. 상단 카드만 재시도 버튼으로 대체.
- 오프라인: 입력은 받고 로컬 큐에 넣는다(10의 "로컬 우선 저장" 문구 근거). 동기화 규칙 **미정**.

## 6. 데이터
- 조회: 오늘 기록 유무, 연속 기록 일수, 최근 기록 3건.
- 전송: 본문(1~200자, 필수) + 고른 기분(`userHint`, **필수**). 감정 세기는 받을 필드가 없어 아직 안 보낸다.
- 날짜 경계: "오늘"의 기준 시각 **미정**(07 뱃지의 "04시 기록"과 충돌 가능).

## 7. 미정

- 과거 날짜 소급 기록 허용 여부
- 오프라인 작성 큐와 동기화 충돌 규칙

### 2026-10-20 인사말과 그림 자리
- **인사말이 "님" 한 글자만 둘째 줄에 남겼다.** 닉네임에 띄어쓰기가 들어가면("말랑한 구름이")
  그 자리에서 줄이 갈린다. 줄을 우리가 먼저 나눈다 - `안녕하세요,` / `{닉네임}님` 두 줄 고정.
  긴 닉네임은 둘째 줄에서 말줄임(`numberOfLines={2}`). 어떤 닉네임이 와도 머리 높이가 같다.
- **빈 그림 자리의 물음표를 캐릭터로 바꿨다.** 앱에서 가장 크고 가장 눈에 띄는 빈 칸인데
  기호 하나만 두면 차갑다. `SOSO` 를 투명도 0.35 로 올린다 - 더 진하면 "이게 내 그림인가"로 읽힌다.

## 10. 구현 (2026-10-19) - 날씨에서 감정으로

- 빈 카드 문구가 "아직 오늘의 날씨가 없어요" -> **"아직 오늘의 기분이 없어요"**
- 빠른 감정 칩이 6종 한 줄 줄바꿈에서 **9종 가로 스크롤**로 바뀌었다. 한 화면에 셋이 들어가고
  넷째가 조금 걸치는 폭(`VISIBLE = 3.25`)이다 - 걸쳐 보이는 것이 "더 있다"는 유일한 신호다
- 칩 안에 감정 캐릭터 그림이 들어간다(`EmotionFace`). 색점은 뗐다 - 과일 색은 빨강이 셋이라 뜻을 나르지 못한다
- 칩을 고르면 그 아래에 **감정 세기 게이지**(`EmotionGauge`, -2 ~ +2)가 열렸다.
  **2026-10-25 에 걷어냈다** - 받을 필드가 API 에 없어 고르고 나면 버려지는 값이었다
- 최근 기록 카드의 썸네일이 날씨 아이콘에서 감정 캐릭터로(78px 안에 58). "더보기"(-> 05 캘린더)를 붙였다.
  날씨 시절의 색 그라디언트는 걷어냈다 - 면은 `faceBg` 단색이고 경계는 테두리가 잡는다
- 세기 값은 서버로 보내지 않았다 - 받을 필드가 API 에 없었고, 그래서 2026-10-25 에 UI 째로 걷어냈다

## 11. 구현 (2026-10-20) - 기분 필수 · 200자 · 공책

ADR [기분 선택 필수와 본문 200자](../adr/2026-10-20-기분-선택-필수와-본문-200자.md).

- **기분이 필수가 됐다.** 서버는 `DIARY_EMOTION_REQUIRED`(400)로 거절하고 앱이 먼저 막는다.
  칩은 "보조 힌트"에서 **1단계**로 올라갔다 - 안 눌러도 되는 버튼은 안 눌린다.
- **본문 상한 500 -> 200.** 화면의 약속("하루 한 줄")과 상한이 어긋나 있었다.
  `app.diary.max-content-length` 와 앱의 `MAX_CONTENT_LENGTH` 가 같은 값이어야 한다. DB 컬럼은 500 그대로.
- **단계 머리**(`StepHead`)가 생겼다. 번호 동그라미는 자로 잰 원이 아니라 `SketchBorder` 로 그린
  손그림 원이고, 끝낸 단계는 번호 대신 체크(`Icon name="check"`, 새로 추가)가 들어간다.
- **쓰는 자리가 공책 한 장이 됐다**(`NotePaper`, `shared/ui`). 괘선은 1px `View` 가 아니라
  `SketchLine` 이고, **괘선 간격과 글줄 높이가 같은 값(28)**이라 글자가 줄 위에 앉는다.
  위 귀에 `Tape` 를 한 장 붙였다.
- 전송 버튼이 알약에서 나와 화면 폭을 쓰는 `xlarge` 가 됐다. 라벨은 "기록" -> **"오늘 그리기"** -
  무엇이 일어나는지를 버튼이 말한다.
- 칩 줄의 바깥 여백 보정이 16 에서 **28**(`gutter.wide`)로 바뀌었다. `Screen width="wide"` 가 주는
  실제 여백과 달라 칩이 화면 끝까지 밀리지 않고 있었다.
- 프로토타입(`prototype.html`)도 같은 모양으로 고쳤다. 공책 괘선은 거기선
  `repeating-linear-gradient` 다 - RN 과 달리 웹은 선을 손으로 긋지 않는다.

### 같은 날 - 쓰는 자리가 접힌 선 아래로 내려가 있었다

처음 올린 배치는 **150 짜리 정사각 그림 자리 + 제목 + 설명을 카드에 담아 맨 위에 뒀다**(254).
그 아래 칩, 그 아래 공책이라 390x844 에서 공책이 화면 끝에 걸치고 버튼은 잘렸다 -
홈에 들어오면 **쓸 곳이 안 보인다.** 받은 말: "홈에 글쓰는 곳이 없잖아."

- **빈 그림 자리를 눕혔다**(254 -> 94). 카드를 걷어내고 점선 칸 하나에 캐릭터와 설명을 가로로 넣는다.
  "앞으로 생길 것"의 자리가 아직 아무것도 없는 동안 화면의 절반을 먹고 있었다.
  점선과 캐릭터가 남아 있어 **"여기에 그림이 생긴다"는 말은 그대로** 한다
- 별도로 떠 있던 "AI 그림 영역" 각주를 설명 한 줄에 합쳤다 - "기분을 고르고 한 줄 쓰면
  여기에 AI 그림이 나타나요". 한 줄이 빈 칸의 뜻과 두 단계를 같이 말한다
- 덩이 사이 간격을 `Screen` 기본 24 에서 **16** 으로(이 화면만). 세 틈에서만 24 가 샜다
- `Screen` 의 ScrollView 에 **키보드 처리 3종**을 넣었다(모든 화면에 적용).
  특히 `keyboardShouldPersistTaps` 가 없으면 키보드가 떠 있을 때 감정 칩이나 버튼의
  **첫 탭이 먹혀** 사용자는 버튼이 고장 났다고 읽는다
- 검증: 프로토타입을 390x844 로 헤드리스 렌더해 **빈 상태와 쓴 상태 둘 다** 눈으로 확인했다.
  세기 게이지를 연 상태에서도 버튼이 탭바 위에 남는다
