# 03 AI 생성 중

## 1. 목적
기록 전송 후 AI가 감정 분석 + 이미지 생성을 하는 동안의 대기 화면.

## 2. 진입 / 이탈
- 진입: 02에서 "기록" 전송 직후.
- 이탈: 성공 -> 04 결과 / 실패 -> 02로 복귀하며 에러 안내.
- 뒤로가기로 빠져나갈 수 있는지 **미정** -> 기본은 **허용, 생성은 백그라운드 계속**.

## 3. 화면 구성

기다리는 사람에게 필요한 넷을 위에서 아래로 쌓는다. **확신 -> 근거 -> 예상 -> 빠져나갈 길.**

| 순서 | 요소 | 내용 |
|---|---|---|
| 1 | 딤 배경 | 02 위에 덮는 오버레이. **누르면 접힌다** |
| 2 | 테이프 | 카드 위 귀에 한 조각(크라프트). 붙여 둔 종이로 읽히게 한다 |
| 3 | 제목 + 물결 밑줄 | "오늘을 그리고 있어요" + `SketchLine` |
| 4 | 그림 자리 | **색연필이 과일 하나를 칠해 나가는 액자**(`DrawingBoard`). 로더를 겸한다 |
| 5 | 입력 원문 | 방금 쓴 한 줄을 그대로. 최대 3줄 |
| 6 | 기다림 안내 | 경과에 따라 바뀌는 한 줄. **진행률이 아니다** |
| 7 | 행동 | "나중에 볼게요". 폴링이 멈춘 뒤에는 "지금 확인하기"가 앞에 선다 |
| 8 | 탭바 | 오버레이가 덮지 않는다. 다른 탭으로 나가도 생성은 계속된다 |

- 접으면(=나중에 볼게요 / 딤 누르기) 딤이 걷히고 02 흐름 안에 같은 카드의 **띠 모양**(`variant="strip"`)이 남는다.
  작은 그림 자리 + 원문 한 줄 + "다 그리면 여기 그대로 나타나요"뿐이고 조작은 없다.
- 04 상세(`/diary/[id]`)에서는 딤 없이 카드만 선다. 덮을 화면이 뒤에 없고, 접을 것도 없다.

## 4. 동작
- **진행 문구는 끝까지 하나다.** 서버가 단계 이벤트를 주지 않으므로 "①감정 분석 ②이미지 생성"처럼
  단계를 표시하면 시간이 지날 때마다 넘어가는 가짜 진행률이 된다(7장).
- 바뀌는 것은 **얼마나 기다렸나**뿐이다: 0s / 20s / 60s / 300s 네 단계의 안내 문구.
  기준은 카드가 뜬 시각이다 - 서버가 생성 시작 시각을 주지 않는다.
- 그림 자리의 색연필은 2.6초에 한 번 왕복한다. 비율을 말하지 않고 "되고 있다"만 말한다.
- 최소 노출 시간을 두어 깜빡임을 막는다(권장 800ms). **아직 안 넣었다** - 폴링 간격이 1초라
  오버레이가 뜨면 최소 1초는 보인다. 서버가 빨라지면 그때 넣는다.

## 5. 상태
- 로딩: 이 화면 자체가 로딩 상태.
- 타임아웃: **폴링을 5분에서 멈춘다**(확정, 2026-10-20). 간격도 늦어질수록 늘린다 -
  30초까지 1초, 2분까지 3초, 5분까지 10초. 1초로 영원히 두드리면 배터리를 먹고,
  상한이 없으면 에러 처리를 안 한 것과 같다.
  멈춘 뒤에는 카드가 마지막 안내로 바뀌고 **"지금 확인하기"**(1회 조회)를 준다.
  "나중에 알려드릴게요"(푸시)는 알림 도메인이 생기면 여기에 붙는다 - 7장.
- 에러: 분석 실패 / 이미지 실패를 구분한다. 이미지만 실패하면 **텍스트 결과만이라도 04로 보낸다**.
- 부적절 입력 차단(모더레이션) 시 문구가 다르다 -> **미정**.

## 6. 데이터
- 생성 작업 id로 폴링 또는 스트리밍. 방식 **미정** -> `llm-integration`.
- 실패 시 재시도는 사용자 명시 행동으로만. 자동 재시도 금지(비용).

## 7. 미정

- 진행 단계 표시 - 현재는 단일 문구. 서버가 단계 이벤트를 주지 않는다.
  **단계를 보여주려면 서버가 먼저 바뀌어야 한다** - 앱에서 시간으로 흉내 내지 않는다
- 생성 중 앱 종료 후 복구, 완료 푸시 알림(`notification` 도메인이 생기면 5장의 5분 상한과 이어진다)
- 부적절 입력(모더레이션) 차단 문구
- 최소 노출 800ms (4장)

## 8. 구현 (2026-10-20)

- 화면: `app/src/features/diary/ui/GeneratingCard.tsx` (홈 탭 안에서 상태로 분기)
- 그림 자리: `app/src/features/diary/ui/DrawingBoard.tsx`, 물결 밑줄: `app/src/shared/ui/SketchLine.tsx`.
  둘 다 `/sketch-gallery` 에서 실제 기기의 모습을 볼 수 있다
- 접기: 홈(`app/app/(tabs)/index.tsx`)이 `minimized` 를 쥔다. 생성이 끝나면 되돌아간다 -
  한 번 접은 것이 영구 설정이 되면 다음 기록의 03 을 못 본다
- 서버: 저장 커밋 후 `@TransactionalEventListener` + `@Async`, 결과 반영은 REQUIRES_NEW 트랜잭션
- 확정: 자동 재시도 없음, 이미지만 실패하면 DONE으로 04까지 보냄, 재생성 하루 3회
- 폴링: 앱이 `GET /api/v1/diaries/today` 를 호출한다. 서버 푸시 아님.
  간격과 5분 상한은 `app/src/features/diary/hooks/useDiary.ts` 의 `POLL_STEPS` 한 곳
  (카드의 마지막 안내도 같은 값 `POLL_GIVE_UP_MS` 를 본다)

### 그림 자리를 왜 이렇게 그렸나

- **빙글 도는 원도 막대도 쓰지 않는다.** 이 체계의 기다림은 차오르는 빗금이다(`hand-drawn-ui` 5장).
  불확정 막대조차 "막대"라서 차오르는 것으로 읽혀 가짜 진행률이 된다
- 그려지는 것은 **꼭지 달린 둥근 과일 하나**다. 감정 아홉이 전부 과일이라 어느 하나로도 읽히지 않는다 -
  판정 전에 특정 감정을 그리면 결과를 미리 말해 버린다
- 빗금을 액자 전체에 깔지 않는다. 면이 꽉 차면 그림이 아니라 무늬가 된다
- 덮개(아직 안 칠한 쪽)와 연필이 **같은 값**으로 움직인다. 둘이 어긋나면 연필이 허공을 칠한다.
  덮개는 9도 눕혔다 - 수직으로 자른 경계는 손이 쓸고 간 자리로 보이지 않는다
- **밑그림(윤곽선)은 덮개보다 위다.** 처음에는 윤곽까지 덮었는데, 시뮬레이터에서 보니 과일이
  반쪽짜리 덩어리로 보였다. 종이에는 연필 선이 먼저 있고 색이 나중에 올라간다 - 그 순서가 맞다
- 연필은 들어오고 나갈 때 흐려진다. 액자 왼쪽 벽에서 반쯤 잘린 자루가 튀어나오면 그림이 아니라 글리치다
- 빗금은 선마다 농도가 다르다(seed 고정). 같은 농도로 그은 빗금은 색연필이 아니라 패턴이다
