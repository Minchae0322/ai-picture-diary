# 04 오늘의 결과 · AI 이미지

> 시안: [9:2](https://www.figma.com/design/zbYEQIRk1ttPOFzojh2hcL/AI-%25EA%25B0%2590%25EC%25A0%2595-%25EB%2582%25A0%25EC%2594%25A8%25EC%259D%25BC%25EA%25B8%25B0---Web-App-Sketch?node-id=9-2) · 탭: 홈 흐름 · 갱신: 2026-09-21

## 1. 목적
생성된 그림과 감정 판정을 보여주고 저장·재생성·공유를 고르게 한다.

## 2. 진입 / 이탈
- 진입: 03 완료 직후, 오늘 기록이 이미 있을 때의 홈 탭, 05 캘린더 날짜 탭(과거 날짜도 같은 레이아웃 가정).
- 이탈: 상단 "←" -> 이전 화면 / "업로드" -> 08 커뮤니티.

## 3. 화면 구성
| 순서 | 요소 | 시안 레이어 | 내용 |
|---|---|---|---|
| 1 | 헤더 | `9:x` | "← 2026.08.24" |
| 2 | 그림 | `AI Artwork (생성 결과)` | 정사각 추정. `ai-tag` "AI generated" 뱃지 필수 |

## 4. 동작
- "저장": 기록 자체는 생성 직후 자동 저장된다. 이 버튼은 **그림을 기기 사진첩에 내려받는** 것이다(2026-10-10 확정).
- "다시 그리기": 같은 원문으로 이미지만 재생성. 03으로 되돌아간다. **횟수 제한 필요**(비용) - 값 미정.
- "업로드": 커뮤니티 공개 = 08 피드에 게시. 누르면 공개 범위를 먼저 묻는다. 익명 규칙 **미정**.
- 뱃지 카드는 이번 저장으로 새로 얻은 것이 있을 때만 노출. 없으면 영역 자체를 뺀다.
- "AI generated" 표기는 제거 대상이 아니다(생성물 고지).

## 5. 상태
- 로딩: 과거 날짜로 진입 시 이미지 로딩 -> 블러 플레이스홀더.
- 빈: 이미지 실패 + 텍스트만 있는 경우 -> 그림 자리에 "그림을 만들지 못했어요 · 다시 그리기".
- 에러: 저장 실패 시 화면 유지하고 토스트 + 재시도. 화면을 벗어나지 않는다.
- 감정 점수 범위는 06 그래프의 축(-3~+3 추정)과 같은 값을 쓴다.

## 6. 데이터
- 일기 1건 = 원문 + 감정(Emotion enum) + 점수 + AI 코멘트 + 이미지 URL + 생성 메타(모델·프롬프트 버전).
  **AI 코멘트는 저장하되 04 화면에 띄우지 않는다**(2026-10-10). 서버 응답에는 그대로 있다.
- 이미지 저장·서빙은 `file-upload-storage`. 원본 보존, 목록용 썸네일 별도.

## 7. 미정

- 이미지 내보내기(OS 공유 시트). 현재 "업로드"는 커뮤니티 게시로 확정했다
- 그림 내려받기의 실제 구현 - `expo-media-library` 가 아직 없어 안내 알림만 띄운다
- **덧그린 획을 어디에 저장할 것인가** (2026-10-20). 지금은 메모리에만 있어 화면을 벗어나면 사라진다.
  두 길이 있고 둘 다 결정이 필요하다.
  1. **획을 JSON 으로** - `tb_diary_drawing`(또는 `tb_diary` 의 컬럼) 하나면 된다. 용량이 작고
     나중에 되돌리기·수정이 가능하다. 다만 스키마 변경이라 `sql/patch` + 문서가 먼저다
  2. **합친 그림을 파일로** - 보기에 가장 단순하지만 **우리는 오브젝트 스토리지가 없다**
     (그림도 picsum URL 을 기기가 직접 받는다). 스토리지를 먼저 정해야 한다
  - 1번을 권한다 - 지금 없는 것을 새로 들이지 않고도 된다
## 8. 구현 (2026-09-21)

- 화면: `app/src/features/diary/ui/DiaryResult.tsx`
- API: `GET /api/v1/diaries/{id}`, `POST /api/v1/diaries/{id}/regenerate`
- 확정: 감정 9종, 기분 점수 -3~+3, 다시 그리기 하루 3회, "AI generated" 표기 고정, 생성 직후 자동 저장
- 이미지 로드 실패 시 "그림을 만들지 못했어요"로 대체

### 2026-10-20 액션 세 칸이 한 줄로 들어간다
- "다시 그리기"가 `다시그리 기` 로 **접혀 있었다.** 알약이 두 줄로 부풀어 옆 버튼과 높이도 어긋났다.
- 원인은 글자 길이가 아니라 **여백이었다.** `fill` 로 폭을 셋이 나누면 칸당 약 103인데,
  거기에 `large` 버튼의 좌우 여백 24가 그대로 들어가 글자 자리가 55밖에 남지 않았다.
  `styles.fill` 에 적어 둔 좁은 여백이 뒤따라오는 인라인 스타일에 덮이고 있었다.
- 고친 것: `fill` 이면 여백을 8로, 글자는 한 단계 작게(`font.sm`), 그리고 **라벨은 한 줄 고정**.
- 라벨도 `다시그리기` -> `다시 그리기` 로. 도메인 어휘의 띄어쓰기를 따른다.

### 2026-10-20 덧그리기 (그림 위에 펜)
- AI 가 그려 준 그림 위에 **직접 덧그릴 수 있다.** 그림 오른쪽 위 "덧그리기"로 들어간다.
- **전체 화면 모달이다.** 04 는 스크롤 안에 있어서 거기서 손가락을 끌면 스크롤과 그리기가
  같은 제스처를 두고 싸운다. 그릴 때는 스크롤 없는 화면을 따로 띄운다 - 그림도 더 크게 보인다.
- **새 라이브러리를 들이지 않았다.** 손가락 추적은 RN 내장 `PanResponder`,
  획은 이미 쓰는 `react-native-svg`. 제스처 라이브러리나 Skia 를 더하면 앱이 같이 무거워진다.
- 도구 5종 + 지우개. **굵기·투명도만 바꾸지 않는다** - 긋는 방식 자체가 다르다.

| 도구 | 어떻게 그리나 |
|---|---|
| 연필 | 얇고 톱니(`strokeDasharray`). 종이 결에 걸린 흑연 |
| 색연필 | 같은 선을 **세 번** 조금씩 어긋나게. 왁스가 겹쳐 쌓인 질감 |
| 사인펜 | 한 번에 진하게. 끝이 둥글다 |
| 형광펜 | 넓고 연하다(0.28). 끝이 **각지다**(butt) - 납작한 펜촉 |
| 붓 | 빠를수록 가늘다. 구간마다 굵기를 달리해 여러 토막으로 그린다 |

- 지우개는 **픽셀이 아니라 획을 지운다.** 손가락이 닿은 획을 통째로 덜어낸다.
- **획은 Skia 로 그린다**(2026-10-20 전환). 처음에는 `react-native-svg` 였는데 색연필에서 막혔다 -
  SVG 로 결을 내려면 `strokeDasharray` 뿐인데 그 값은 **주기적으로 반복**돼 결이 아니라 구슬을 꿴 것처럼 보였다.
  Skia 의 `DiscretePathEffect` 는 경로를 토막 내 **토막마다 난수로** 밀어 주므로 주기가 없다.
  색연필은 이걸 흔들림·굵기·진하기를 달리해 세 번 겹친다.
  Skia 를 들인 둘째 이유는 `makeImageSnapshot` 이다 - 저장 문제(7장)의 길이 열린다.
- **아직 기기 안에만 있다.** 화면을 벗어나면 사라진다 - 아래 7장 참고.

## 9. 구현 (2026-09-22)

- 액션 3개를 시안대로 배치했다: 다시그리기 / **저장**(그림 내려받기) / **업로드**(08 커뮤니티 게시).
  2026-10-10 에 "저장됨 비활성 / 공유" 에서 바꿨다 - 자동 저장은 안내할 것이지 버튼으로 둘 일이 아니었다
- "업로드" = 08 커뮤니티 게시로 확정. `POST /api/v1/community/posts { diaryId }`. 본문·감정·닉네임은 서버가 일기와 프로필에서 복사한다
- 뱃지 획득 카드: `GET /api/v1/badges`에서 `earnedAt`이 그날인 뱃지만 보여준다. 판정은 서버가 일기 완료 직후에 한다
- 과거 날짜 모드: `app/app/diary/[id].tsx`. 같은 레이아웃을 쓰되 공유 버튼은 주지 않는다

## 10. 구현 (2026-10-19) - 날씨에서 감정으로

- 판정 칩의 색점이 **감정 캐릭터**로 바뀌었다("행복한 · 기분 +2"). 면은 물들이지 않는다 -
  과일 색과 캐릭터가 같은 계열이라 그림이 묻힌다
- 액션이 "저장됨(비활성) / 공유" -> **"저장(그림 내려받기) / 업로드"** 로 바뀌었다
- "AI generated" 표기는 그대로다
- AI 코멘트는 화면에서 빼 둔 상태를 유지한다(6장). 서버는 여전히 내려주고 저장한다
