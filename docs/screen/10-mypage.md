## 4. 동작
- 각 행은 현재값을 오른쪽에 보여준다. 값이 없으면 행을 숨기지 말고 "설정 안 함".
- 리마인더: OS 알림 권한 요청 지점(`notification`). 거부 상태면 값 대신 "알림 꺼짐 · 설정 열기".
- 일기 잠금 ON이면 앱 재진입 시 생체/PIN 인증. 잠금 시 05·06의 노출 범위 **미정**.
- AI 그림 스타일은 04 생성 프롬프트에 직결(`prompt-and-eval`). 스타일 목록 **미정**.
- **계정 삭제가 시안에 없다.** 두 스토어 모두 필수 -> "계정 · 로그아웃" 하위에 반드시 넣는다.

## 5. 상태
- 로딩: 통계 3칸 스켈레톤. 설정 목록은 로컬 값이라 즉시 노출.
- 빈: 기록 0건이면 통계 0으로 표시(숨기지 않는다).
- 에러: 통계 조회 실패 -> 통계 영역만 재시도. 설정은 영향 없음.

## 6. 데이터
- 통계 3종은 서버 집계. 연속 일수는 02·06과 같은 계산을 쓴다.
- 내보내기는 서버 생성 후 다운로드. 대량이면 비동기 + 완료 알림(`batch-and-scheduler`).
- "로컬 우선 저장" 문구 = 오프라인 작성 후 동기화 전제. 충돌 규칙 **미정**.

## 7. 미정
- 설정 하위 화면: 리마인더, AI 그림 스타일, 데이터 내보내기, 계정·로그아웃 (테마 변경은 09로 확정, 일기 잠금은 값 토글까지 구현)
- **계정 삭제 동선과 유예 기간** - 두 스토어 필수. 인증이 붙어야 의미가 생긴다
- 리마인더 실제 발송과 알림 권한 요청
- 일기 잠금 ON일 때의 실제 잠금(생체/PIN)과 05·06 노출 범위
- 동기화 충돌 해결 규칙(로컬/서버 우선)
- 내보내기 포맷별 포함 범위(이미지 포함 여부)

## 8. 구현 (2026-09-22)

- 화면: `app/app/(tabs)/my.tsx` · 프로필 카드 `app/src/features/profile/ui/ProfileCard.tsx` · 설정 행 `app/src/shared/ui/ListRow.tsx`
- API: `GET /api/v1/profile`, `PATCH /api/v1/profile/settings` + 통계는 `GET /api/v1/diaries/overview`(총 기록·연속)와 `GET /api/v1/badges`(뱃지 수)
- **통계 3종을 한 엔드포인트로 합치지 않았다.** 도메인이 다르고 앱이 세 쿼리를 병렬로 부르면 그만이다. 연속 일수는 02·06과 같은 계산(`StreakCalculator`)이다
- 인증이 없어 프로필 행이 미리 없다. 첫 조회에서 만든다(닉네임은 `NicknameGenerator`가 무작위로, 가입일 = 오늘). 그림 스타일 초깃값과 닉네임 길이 상한은 `app.profile.*` 설정이다
- 시안의 6행에 **"뱃지" 행을 하나 더했다** - 07 진입 동선이 시안에 없었다(07 문서 2장의 미정)
- 아직 준비 안 된 행은 동작하는 척하지 않고 "아직 준비 중이에요"를 띄운다
- 값이 없는 행은 숨기지 않고 "설정 안 함"을 보여준다(4장 규칙)
