# 11 로그인

시안에 없는 화면이다. 01 온보딩의 "이미 계정이 있어요"가 갈 곳이 없어 홈으로 보내고 있었는데, 그 자리를 채운다.

## 1. 목적
이미 계정이 있는 사람이 기존 기록으로 돌아간다. 처음 쓰는 사람은 01의 "무료로 시작하기"로 홈에 바로 들어간다 - 이 화면을 거치지 않는다.

## 2. 진입 / 이탈
- 진입: 01 온보딩의 "이미 계정이 있어요"
- 이탈: 로그인 성공 -> 02 홈 / 뒤로 -> 01 온보딩 / "회원가입" -> 가입 화면(**미정**)

## 3. 화면 구성
| 순서 | 요소 | 내용 |
|---|---|---|
| 1 | 뒤로 | 01로 돌아간다 |
| 2 | 헤드라인 | "다시 만나서 반가워요" |
| 3 | 서브카피 | "그동안의 기록은 그대로 기다리고 있어요." |
| 4 | Apple로 로그인 | 검정 채움, 흰 글자 + 애플 마크 |
| 5 | Google로 로그인 | 흰 면 + 테두리, 4색 G 마크 |
| 6 | 구분선 | "또는" |
| 7 | 회원가입 | 보조 버튼 |
| 8 | 약관 고지 | "계속하면 이용약관과 개인정보처리방침에 동의하는 것으로 봅니다." |

버튼 셋은 바닥에 모은다. 글은 제자리에 두고 남는 공간을 버튼 묶음이 먹는다.

## 4. 동작
- 세 버튼 모두 **아직 인증이 없다.** 누르면 "인증이 아직 붙지 않았어요"를 알리고 홈으로 보낸다. 되는 척하지 않는다.
- 뒤로는 01로 돌아간다. 홈으로 빠지지 않는다.

## 5. 상태
- 로딩: 없음. 인증이 붙으면 소셜 창을 띄우는 동안 버튼을 잠가야 한다
- 에러: 없음. 인증이 붙으면 취소/실패/네트워크 세 가지를 구분해 보여준다
- 권한: 없음

## 6. 데이터
- 서버 호출 없음. 인증이 붙으면 토큰을 받는다.
- **토큰은 AsyncStorage에 두지 않는다.** 평문이라 `expo-secure-store`가 필요하다(프로젝트 스킬 즉시 금지 항목).

## 7. 미정
- 인증 공급자 연동 전체 -> `spring-auth`. 서버에 사용자·세션 테이블이 아직 없다
- 회원가입 화면. 이메일 가입을 받을지, 소셜만 받을지
- 비회원 체험과의 관계. 01에서 바로 들어온 사람이 나중에 계정을 붙이면 기록을 어떻게 잇는지
- 로그아웃 후 이 화면으로 돌아오는 경로(10 마이페이지의 "계정 · 로그아웃")

## 8. 구현 (2026-10-10)

- 화면: `app/app/login.tsx` · 프로토타입: `docs/screen/prototype.html` 의 `viewLogin()`
- 01의 링크가 `router.push('/login')` 로 바뀌었다. CTA("무료로 시작하기")는 그대로 홈이다

> [!IMPORTANT]
> **소셜 버튼의 마크와 색은 임시다.** 애플과 구글은 공식 버튼 규정이 있다.
> - 애플: 지정 로고·문구·최소 높이 44pt·허용 색(검정/흰색/외곽선)만 쓸 수 있다. 벗어나면 심사에서 걸린다.
>   붙일 때 `expo-apple-authentication` 의 기본 버튼을 쓰면 규정이 저절로 지켜진다.
> - 구글: 공식 4색 G 마크와 지정 색을 요구한다. 임의로 그린 마크는 브랜드 가이드 위반이다.
>
> 지금 `Icon.tsx` 의 `apple` / `google` 은 **자리를 잡기 위한 도형**이다. 배포 전에 공식 에셋으로 바꾼다.

- 규정색은 토큰으로 두지 않았다. 애플 검정과 구글 흰색은 브랜드가 정한 값이라 테마를 따라 바뀌면 안 된다.
  그래서 `login.tsx` 안에 상수로 박아 두고 그 이유를 옆에 적었다
- 구글 마크는 네 색이 규정이라 `Icon` 의 `color` 인자를 무시한다. 다른 아이콘과 호출 모양을 맞추려고
  인자는 받되 쓰지 않는다(`google: (_s: string) => ...`)
- 아직: 인증, 회원가입 화면, 로딩·에러 상태
